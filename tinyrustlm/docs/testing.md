# Testing

## Purpose

Tests prove each low-level primitive before the runtime claims TinyLM-16M support.

## Constraints

Tests use Rust's built-in test framework. The core runtime and no-crate tool tests still avoid extra test harness dependencies; the Local Connect policy gate deliberately uses `serde`/`serde_json` because browser-exported JSON is a security boundary. The workspace denies missing public Rust documentation, and release/test helpers run strict rustdoc checks for the runtime library plus Rust tool binaries.

The `share-metadata-kit-exec` browser smoke now treats peer companion inventory as part of the generated local share-kit contract. It requires the share-kit descriptor flag, executes `write-peer-companion-inventory` and `inspect-peer-companion-inventory`, checks the printed `Peer companion inventory:` output, parses the generated JSON, and verifies that the inventory remains metadata-only while binding the expected state, receipt ledger, peer URL, contact card, piece count, piece-store byte/quota/SHA-256 evidence, and `ready-after-rust-reverify` serve plan.

`eng/verify-tinyrustlm-ui.ps1` and `eng/verify-tinyrustlm-ui.sh` are the lightweight UI contract gates. They run the no-crate Rust browser harness against the checked-in app tree, start the Rust loopback static server, rerun the harness against `http://127.0.0.1:<port>/app/`, and write `artifacts/reports/tinyrustlm-ui-verification.json`. Use `-RunBrowserSmoke` in PowerShell or `RUN_BROWSER_SMOKE=1` in Bash to also run the headless `source-options-ui`, `local-memory-deck-ui`, `local-connect-approval-ui`, `local-connect-endpoint-ui`, `local-connect-rust-endpoint-ui`, and `peer-status-live-ui` smokes. Those reports prove the Local `.slm`, UAIX memory deck, Hugging Face, P2P import, and Advanced setup controls open implemented source panels, that Local Connect approval presets, risk warnings, category-bound app approvals, endpoint inventory, dry-run action gating, and the Rust Local Connect endpoint stay aligned, and that live peer readiness checks fetch only `minimodel.peer_status.v0.json` metadata from the Known peer URL. Use `-RunDeepBrowserSmoke` or `RUN_DEEP_BROWSER_SMOKE=1` when a release candidate needs heavyweight end-to-end conversion and P2P execution proof; the wrapper then runs `hf-conversion-kit-safetensors-exec`, `hf-conversion-kit-review-exec`, `hf-conversion-kit-review-reject-exec`, `hf-conversion-kit-gguf-exec`, and `hf-p2p-import-kit-exec`, recording `deep_browser_smoke_requested`, `deep_browser_smoke_modes`, and per-mode report paths in the same `tinyrustlm.ui_verification.v0` schema. Use `-BrowserSmokeModes hf-conversion-kit-safetensors-exec` in PowerShell or `TINYRUSTLM_BROWSER_SMOKE_MODES=hf-conversion-kit-safetensors-exec` in Bash to rerun one expensive branch without repeating the quick UI smoke set; comma-separated mode lists are supported, and the legacy `hf-conversion-kit-exec` compatibility mode still runs all conversion branches in one process. Each browser smoke has a default 1800-second timeout and records `browser_smoke_timeout_seconds`; use `-BrowserSmokeTimeoutSeconds <seconds>` or `BROWSER_SMOKE_TIMEOUT_SECONDS=<seconds>` to shorten or lengthen the limit, and timed-out modes write their report file before the wrapper fails. The Windows CI workflow runs the PowerShell gate with `-RunBrowserSmoke` on normal pushes, exposes `run_deep_browser_smoke` as a manual workflow-dispatch option that runs `-BrowserSmokeModes hf-conversion-kit-safetensors-exec,hf-conversion-kit-review-exec,hf-conversion-kit-review-reject-exec,hf-conversion-kit-gguf-exec,hf-p2p-import-kit-exec`, validates `tinyrustlm.ui_verification.v0` through `UiVerificationReportIsMachineReadableWhenPresent`, and uploads the UI report plus per-mode smoke reports as `tinyrustlm-ui-verification`.

## Coverage Goals

Changed code should target at least 75% automated coverage. Each new or changed method parameter should have a related automated test for its accepted behavior, rejection behavior, or boundary effect. Standalone test files should mirror the tested source filename with `_test` appended before the extension; inline Rust unit tests remain acceptable where the module already uses that pattern.

## Binary Formats

The tiny test models use the same `.slm` v1 format with hidden size 8, one layer, two heads, head dimension 4, ffn size 16, and context 16. The byte-tokenizer f32/q8_0/q4_0 tiny fixtures use vocab 260 and must generate the same deterministic output. The tied-output tiny fixture also uses vocab 260, omits `output.weight`, and must generate through the `tok_embeddings.weight` projection route only because the v1 tied-output flag is set. The BPE tiny fixture uses vocab 262 and must prove prompt `the` merges into token `261` before generation. The TinyLM-16M f32, q8_0, and q4_0 smoke models use hidden size 512, four layers, eight heads, ffn size 2048, and context 512.
