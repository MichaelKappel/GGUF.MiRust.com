# Safetensors Candidate Review Memory

`review-safetensors-candidate` adds a no-crate pre-extraction review artifact for real trained safetensors checkpoints, and the extraction, conversion, and browser-bundle commands can now consume that artifact as their final review-bound argument.

The command accepts an input safetensors file, target source shape, output quantization, source model id, source model SHA, source config checksum, source tokenizer checksum, source license route, output review path, optional reference prompt route, reference output checksum, eval-cases route, source config route, and source tokenizer route.

The review report records source file, source/config/tokenizer identity, hex64 config/tokenizer/reference-output checksums, optional config and tokenizer artifact routes, local JSON artifact status/kind/checksum/byte/detail evidence when those routes resolve to files, header checksum, tensor-directory checksum, source-plan mapping checksum, architecture family, tensor-layout strategy, tokenizer strategy, quantization target, parameter count, matched tensor count, raw source bytes, target estimated serialized `.slm` bytes using writer alignment rules, BPE tokenizer section byte accounting for `manifest-bpe-v1` source shapes, comparative f32/q8_0/q4_0 byte estimates, per-quantization selector fit status, `browser_admission_default_strategy=browser-frugal-quantized`, browser-admission preferred and fallback quantization fields, context token limit, KV-cache byte/page budget, conversion status, converter gap status, reference-output route, runtime-smoke placeholder route, eval-cases route, eval-sidecar placeholder route, and `required_next_gate=extract-raw-f32-tensors`. BPE source-shape reviews now require a checksum-matched local compatible BPE tokenizer JSON artifact, so exact estimates use imported token and merge rows instead of template tokenizer rows.

When config or tokenizer routes resolve to local JSON, the review parses the artifact, requires the supplied checksum to use the `0x` plus 16-hex TinyRustLM format and match the local text checksum, records artifact evidence rows, and writes normalized detail rows. The optional reference-output checksum uses the same hex64 format. Config detail echoes `model_type`, vocab size, hidden size, layer count, attention heads, KV heads, FFN size, and max context when present. Tokenizer detail echoes `model.type`; BPE routes also echo vocab entry count, max token id, and merge count, and `manifest-bpe-v1` shapes require tokenizer JSON with `model.type=BPE`, numeric `vocab` ids, and `merges`. Compatible local BPE tokenizer JSON uses raw byte fallback ids for merge inputs, leaves TinyRustLM special ids reserved, and emits custom token bytes plus ranked merges into the source manifest; byte-level remapping tokens are rejected before extraction.

Review-bound extraction recomputes the source plan and requires the review version/layout, source path, target model shape, file/header/tensor-directory checksums, source-plan mapping checksum, matched tensor count, raw source bytes, conversion status, and `required_next_gate=extract-raw-f32-tensors` to match before tensor bytes are copied. It also requires reviewed source/config/tokenizer/license/reference/eval routes instead of the pending placeholders, revalidates local config/tokenizer artifact rows including normalized detail when present, recomputes budget rows with the same imported tokenizer rows, then writes `source_review_kind=safetensors-candidate-review`, `source_review_status=validated-before-extraction`, `source_review_checksum`, `source_review_required_next_gate=extract-raw-f32-tensors`, and imported `tokenizer=bpe-v1` rows into the raw `source.manifest` when a compatible BPE artifact was reviewed.

Review-bound conversion requires the requested f32/q8_0/q4_0 output to match the review's `quantization_target`. Review-bound browser bundling requires the requested quantization to match `browser_admission_preferred_quantization`, while `all` remains accepted when the review identifies a browser-fit preferred quantization.

This moves real-checkpoint work forward without writing source directories, converted `.slm` files, browser roots, or assistant-quality claims before reviewed source/config/tokenizer/license/reference/eval routes exist, then keeps the downstream commands bound to that review when it is supplied. Browser admission carries the copied source review fields through admission and selector registry evidence, the BPE fixture path proves review-bound q8_0 bundle admission with explicit eval evidence and `BPE1` model bytes, and the `converted-trained-bpe-registry-file` smoke proves a CLI-reviewed safetensors BPE root renders the computed Source Review checksum before model bytes.
